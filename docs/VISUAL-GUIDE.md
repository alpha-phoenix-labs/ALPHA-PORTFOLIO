# Visual Presentation Guide

## Direction

A restrained editorial engineering portfolio: graphite, warm white, muted slate, and one restrained teal accent. Strong typographic hierarchy, generous whitespace, intentional cropping, and consistent framing.

## Visual system

- **Background:** near-black graphite for cover art; warm white for reading surfaces.
- **Typography:** one strong display face paired with a highly legible sans-serif.
- **Composition:** one focal point per image; avoid dense collage layouts for technical details.
- **Captions:** short, factual, and consistent.
- **Motion:** demonstrate only real interactions; do not imply behavior that is not implemented.
- **Responsive:** check text and images at narrow mobile widths as well as desktop.

## Screenshot standards

For every real screenshot, record capture date, target URL, viewport, and commit/deployment when known. Remove personal data and sensitive information before publication.

Recommended set:
1. Desktop full-page or representative viewport
2. Mobile viewport
3. Hero crop
4. Detail crop showing an actual interface component

Generated visuals must be captioned **Concept mockup — illustrative, not a live screenshot**. Never use generated interface content as evidence of production behavior.

## Review checklist

- [ ] Image rights and attribution reviewed
- [ ] Correct source and capture date recorded
- [ ] Desktop and mobile crops checked
- [ ] No secrets, personal data, or private URLs visible
- [ ] Claims in captions are supported
- [ ] Concept mockups clearly distinguished from real screenshots
